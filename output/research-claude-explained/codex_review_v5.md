1. **High — inconsistency (§5.2, §6.1–6.2).** “Held-out task (any status)” permits “Transfer test only” and prohibits endpoint fitting, yet verification requires “Four development videos of the same task.” Transfer also needs task-specific ranges and fallback means. **Why:** The held-out tasks cannot pass through the specified scoring procedure without data the protocol excludes. **Fix:** Define an evaluation-only calibration bank from development participants, opened at confirmation under a frozen procedure, and state explicitly that its labels supply probes, endpoints and fallbacks without updating the agent.

2. **High — overclaim (§5.4).** “Its submission is verified, so reference numbers cannot be copied into the answer.” **Why:** Arbitrary submitted code can recognize the current input, return a copied reference value there, and use legitimate calculations on every probe. Replay, range checking and testing on other videos do not exclude this behavior. **Fix:** Replace the guarantee with “The checks discourage direct copying but do not establish its absence,” and add input-specific branching, encoded constants and current-video annotation errors to the adversarial suite.

3. **High — logical-gap (§5.2).** “Two with reference values near the feature’s 25th percentile and two near its 75th” must satisfy “both low probes come out below both high probes.” **Why:** Those percentiles can coincide for capped features; the hold-time histogram in `figures/papers/stable_fig2a_features.png` shows a substantial pile-up at five seconds. Correct code returning equal reference values would fail the strict ordering requirement. **Fix:** Require ordering only when reference groups are separated by a predefined meaningful margin; specify tie handling and what happens when four suitable probes do not exist.

4. **High — error (§3, hypothesis table).** “Refuted if … The 95% crossed-bootstrap interval for the difference includes zero.” **Why:** Including zero is inconclusive, not refutation. Conversely, an entirely negative interval excludes zero while contradicting the claimed improvement. “Verification is necessary” also exceeds what one ablation can establish. **Fix:** Distinguish supported, inconclusive and contradicted outcomes; apply §9’s complete decision rule, including the skill safeguard; rename H3 “Verification improves this pipeline.”

5. **High — logical-gap (§8.1, S7).** “Response accuracy is the share of features” responding correctly, followed by “For the direct predictor, which outputs only scores, the predicted change in score follows from the same feature ratios.” **Why:** Feature-level success and score-level success are different quantities. Feature errors can cancel in the score—the proposal’s own motivation—so S7 lacks a common comparison metric. **Fix:** Compare both methods’ predicted score changes against changes computed from transformed reference features, using the same predefined tolerance in score units; report feature-level response separately.

6. **High — overclaim (§3, H5).** “The agent measures movement,” supported by intervention-response accuracy. **Why:** A shortcut using clip duration for durations, inverse clip duration for speeds, and constants for angles could satisfy these transformations without examining movement. Correct transformation ratios also do not establish accurate original measurements. **Fix:** Narrow H5 to “Outputs respond consistently to video retiming,” test these duration-based shortcuts, and interpret response accuracy jointly with absolute feature error.

7. **High — inconsistency (§5.5, §6.3).** Calibration uses “one held-aside development fold,” while final fitting uses “all 111 development participants.” **Why:** The calibration fold must remain excluded from fitting the model being calibrated. Additionally, the ordinary “90th percentile” omits the finite-sample correction, and pooling correlated trials requires a justified calibration unit. **Fix:** Reserve calibration participants permanently, specify per-task or pooled coverage, and use the residual at sorted position \(\lceil0.9(n+1)\rceil\), where \(n\) is the number of valid calibration units. Qualify Figure 28’s guarantee accordingly. See the [cited conformal-prediction procedure](https://arxiv.org/html/2107.07511v6).

8. **High — inconsistency (§5.3).** The task score uses submitted values only “if the feature is verified,” but the final-score control is “computed from the submitted values.” **Why:** The same score symbol appears to denote both a fallback-adjusted score and a raw submission score. The subsequent bound \(\frac1k\sum_f e_f\leq -R\) also does not hold for the final-score reward when feature errors cancel. **Fix:** Define separate raw and fallback-adjusted scores, state which each training arm and evaluation uses, and explicitly restrict the bound to the applicable per-feature reward.

9. **Medium — overclaim (Abstract, §5.4).** “Demonstrations the single-camera student can follow”; filtering checks that “no remaining text refers to panel content.” **Why:** Removing explicit references does not remove decisions that depended on privileged information. A teacher may select a time window or reconstruction setting using evidence unavailable to the student. Testing its final function on other videos does not test whether those choices are learnable. **Fix:** Say the filters test code reuse and remove explicit reference content; identify successful learning of the teacher’s decisions as an empirical question evaluated by S2.

10. **Medium — error (§8.1; `figures/fig_timescale.svg`).** “Durations should grow by a factor of 1.25,” except for “a hold already at the five-second limit.” **Why:** Previously uncapped holds can become capped: 4.5 seconds becomes 5 seconds, not 5.625. Ratios are also undefined when the original value is zero. **Fix:** Use the task’s actual capped transformation, such as \(h'=\min(5,h/0.8)\), and define an absolute-error criterion for zero or near-zero denominators. Update the SVG’s exception.

11. **Medium — error (§2.7; `figures/fig_guess.svg`).** The shrunken predictor tells us “almost nothing about who balances better,” while “only the noisy predictor keeps the differences between people.” **Why:** The shrunken predictor orders everyone correctly, with rank agreement 1.0; the noisy predictor scores 0.8. The distinction is the magnitude of differences, not knowledge of ordering. **Fix:** Replace with: “The shrunken predictor ranks everyone correctly but understates differences fivefold. Rank agreement measures ordering; calibration slope measures compression.”

12. **Medium — inconsistency (§2.1, §5.2–5.3).** “A task score between 0 and 1,” alongside training-fitted endpoints and a permitted range “widened by half its width on each side.” **Why:** Those permitted submissions rescale to \([-0.5,1.5]\), and new reference values can also exceed training endpoints. Neither features nor task scores are consequently confined to 0–1. **Fix:** State that 0–1 describes the training range and that evaluation values may lie outside it, or explicitly specify clipping and apply it consistently. Also define handling when \(U=L\).

13. **Medium — inconsistency (Introduction, Figure 29).** “Sixty participants are sealed before any analysis.” **Why:** §6.2 correctly discloses that these participants already trained the pilot models. The introduction and `figures/fig_split_v5.svg` omit that qualification and imply a stronger separation from prior analysis. **Fix:** Use “reserved before this study’s development, following earlier use in pilot training” consistently; retain the retrospective design and its stated limitation.

14. **Medium — inconsistency (§1).** “The three-camera reconstruction, which exists only for the training videos.” **Why:** §2.9 explicitly uses three-camera reconstructions during evaluation, and the sealed-set comparisons require them. Availability to the agent is being confused with existence in the dataset. **Fix:** Replace with: “Three-camera reconstructions supply training supervision; evaluation reconstructions remain hidden from the agent and are used only for scoring.”

15. **Medium — logical-gap (§5.5).** Training labels come from “the expert pipeline’s feature functions,” but the model supplies “predicted errors of the final features.” **Why:** Error for expert-written code does not automatically predict error for arbitrary agent-written code and annotations. The training-data description also records error and failure but never records the promised GPU-cost target. **Fix:** Describe predictions as expert-route error estimates, validate their usefulness for actual agent submissions, and specify runtime labels or a separate measured-cost lookup.

16. **Medium — error (§2.6).** “SFT imitates; it cannot find a better strategy than the one in its examples.” **Why:** An imitation objective does not impose that mathematical ceiling on generalization; supervised students can outperform teachers. [Born Again Neural Networks](https://arxiv.org/abs/1805.04770) provides a counterexample to the broader claim. **Fix:** Replace with: “SFT learns from fixed demonstrations. RL additionally evaluates newly generated attempts using a reward.”

17. **Medium — logical-gap (§7, Stage 1).** “If the demographic model matches the direct predictor’s rank agreement, age-adjusted rank agreement becomes co-primary.” **Why:** “Matches” has no numerical definition, and §9 never specifies how the additional primary outcome changes the success rule. The method for removing age’s contribution is also unspecified. **Fix:** Define the development-set trigger, the age-adjustment calculation, and whether both primary outcomes must succeed; incorporate that branch into the power simulation and preregistered decision rule.

18. **Medium — undefined-term (Abstract and Introduction).** “A vision-language agent that calls pose, segmentation and reconstruction tools.” **Why:** The reader encounters several foundational terms before receiving their explanations much later. The opening consequently requires the background it is supposed to introduce. **Fix:** Start with plain descriptions: “a program that uses an image-and-text model to select tools that locate joints, outline the person and estimate three-dimensional motion.” Introduce the technical names alongside those descriptions.

19. **Medium — undefined-term (§5–§9).** “Gradient-boosted trees,” “ability quintile,” “unmasked features,” “Kolmogorov–Smirnov tests,” “standardized differences” and “crossed bootstrap.” **Why:** These remain unexplained or are only named, despite being needed to understand the procedure. **Fix:** Define them at first use: successive small decision trees that correct earlier prediction errors; five equally sized ability groups; features retained because references are usable; a comparison of distributions; a mean difference measured relative to spread; and resampling training runs and participants separately. Move unnecessary test names into an appendix.

20. **Medium — logical-gap (§5.3).** “Annotation timing error in seconds.” **Why:** The reward never specifies whether errors at the start and end are added, averaged or otherwise combined. A reader cannot calculate the reward even after understanding its notation. **Fix:** Define the timing term explicitly, including missing annotations, then provide one worked example—for instance, three feature errors totaling 0.6, one verification failure and a mean timing error of one second give \(R=-(0.6+0.5)/3-0.1=-0.467\).

21. **Medium — undefined-term (reproduced figures).** `figures/papers/qwen3vl_fig1_architecture.png`, `lora_fig1.png`, `deepseekmath_fig4_grpo.png` and `pi_distill_fig1.png`. **Why:** These introduce unexplained labels and notation such as “Dense/MoE Decoder,” “DeepStack,” \(A\sim\mathcal N(0,\sigma^2)\), “GAE” and policy/objective expressions. Plain captions do not make the diagrams themselves understandable. **Fix:** Use simplified, attributed diagrams containing only the concepts explained in the main text; place the full originals and their notation keys in an appendix.

22. **Medium — figure-text-mismatch (§2.6, §10; `figures/fig_levers.svg`).** Prompt and harness optimization are labeled “Cost: agent runs only.” **Why:** Both methods also run proposer models, which §10 explicitly counts. “No weights change, so the method is cheap” similarly treats an empirical cost comparison as automatic. **Fix:** Label both “Cost: proposer and agent inference,” and describe their relative expense as something measured under the proposed budget comparison.

23. **Medium — concision (§2.5, §5.1, §7).** The tool inventory appears in both “Tools, harnesses and agents” and “Agent, harness and cache”; the complete stage plan appears in both the table and `figures/fig_stages_v5.svg`. **Why:** These repetitions add substantial length without explaining another concept. The research question arrives only after 22 figures. **Fix:** Keep one full tool inventory and one complete stage plan, place the research question immediately after the introduction, and move optional PPO architecture and LoRA matrix details to an appendix while preserving their short conceptual explanations.

24. **Low — structure (§3, §10).** “By the ICML 2027 submission deadline (expected late January 2027)” and “scope decision dated 6 November.” **Why:** The first inserts publication logistics into the scientific question; the second reads as an internal planning note. **Fix:** Remove the deadline clause from the question and express the scope decision as a scheduled milestone in the timeline.

25. **Low — style (Figure 19; `figures/fig_teacher.svg`).** “A video-language model stops watching”; “Uses the panel to see where the one-camera tools went wrong.” **Why:** These anthropomorphic shortcuts replace descriptions of observable behavior, and “stops watching” overstates what frame-order invariance establishes. **Fix:** Use “Answers become less sensitive to frame order” and “The reference panel helps identify discrepancies in tool outputs.”

The proposal has a clear central comparison and useful introductory explanations, but its verification and transfer procedures are not yet internally complete. Its claims about measurement validity, teacher followability and statistical confirmation exceed what the specified checks establish. Resolve those protocol conflicts, narrow the claims and remove duplicated exposition while making the remaining terminology and figures self-contained.
