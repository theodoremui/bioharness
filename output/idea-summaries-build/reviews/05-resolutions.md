| adversarial-r1 [high] | H3 forecast undefined; a pooled correlation over three bases can pass by ranking bases | Fixed (held-out bases declined) | H3 now uses one scalar forecast, $\hat F=1-(1-sg)^{100}$ from a 300-edit profile, frozen before any sealed outcome is opened; base means are removed (within-base correlation); Williams' test is checked by a bootstrap over configurations within base and over sealed people; the power paragraph states the independence assumption and the three lost degrees of freedom. Held-out bases for tier 2 are declined on cost; tier-2 claims are stated as conditional on three bases. |
| adversarial-r1 [high] | Cold-start comparison substitutes a weaker rule for HGM (HGM pools the node's own evaluations; different event; correlation undefined at zero descendants) | Fixed | Key ideas now state that HGM pools the clade including the node's own evaluations and that one success event (lowering development error by $\delta$ relative to the parent) is shared by every estimator. The prior distinguishes an unevaluated node ($\sigma(w^\top x_a)$) from one evaluated once (one added count). H5 compares Spearman correlation and regret at 0, 5 and 20 descendants. The coding replication keeps HGM's own task counts, and a risk bullet names the adaptation. Figure 6 is titled and captioned as the hypothesis H5 tests. |
| adversarial-r1 [high] | H2 power uses four times the sample size of the composite contrast | Fixed (stronger loop proposers declined) | H2's equivalence test is now on each of the four main effects (2,400 edits per factor level and proposer, half-width near 0.017), with equivalence claimed only if all four pass; the composite (600 edits per cell, half-width near 0.034) serves only the capability slope, and the text says so. H2 is restricted to one-step edits. Running the 480B proposer in tier-2 loops is declined: 2.1 billion tokens at 2,500 tokens per second on an eight-H100 node is about 1,870 H100-hours, more than twice the whole budget. |
| adversarial-r1 [high] | Break-even model uses a different success event from the search it forecasts, and rates and crossover share a cohort | Fixed | $B^{\star}$ now uses the development-event profile $(s_{dev},g_{dev})$, the event a loop's acceptance rule sees; the model is tied to the single-incumbent Meta-Harness-style loop, with OpenEvolve as a secondary check. Rates come from development events and the crossover is observed on selection people, so the two use different cohorts. The crossover is the first 25-step checkpoint after which the refactor arm stays below search alone (handles multiple crossings), and no crossing by 200 evaluation-equivalents is a miss. |
| adversarial-r1 [medium] | The O arm repeats Meta-Harness's trace-access intervention; Figure 1 attributes the gap to structure alone | Fixed | Every arm now receives one feedback channel of fixed format and length; an external-trace control gives cell 1 the O-level summaries from a tracer; the gap statement narrows the O novelty; the outcome table has an "external trace matches O" row; Figure 1 says "hypothesized gap from code structure". |
| adversarial-r1 [medium] | Compute omits selection scoring and refactor validation | Fixed | New rows: selection scoring of accepted candidates (87,900 candidates at 40% of 219,700 loop steps, 5,490 CPU-hours) and refactor profiles and gates (5,400 edits for 6 starting forms and 12 first-seed refactored variants, 2,100 gated refactors, 89M tokens, 1,380 CPU-hours). Totals: about 700 H100-hours, 10.2 billion open-model tokens, about 44,000 CPU-hours. |
